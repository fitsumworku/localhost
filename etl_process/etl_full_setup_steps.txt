================================================================================
FULL LOCAL ETL SETUP AND INTEGRATION TEST STEPS
================================================================================

PURPOSE
=======
This document prepares the current repository for a full local ETL test:

  PostgreSQL app (OLTP source)
      -> Debezium PostgreSQL connector
      -> Kafka topics
      -> Python ETL consumer and transformers
      -> PostgreSQL sampleolapdata (OLAP target)
      -> Airflow orchestration and validation

CURRENT REPOSITORY FACTS
========================

Available:
  - Docker Compose PostgreSQL database: app
  - PostgreSQL host port: 5432
  - Data generators under data_generators/
  - Generated SQL files under data/
  - OLTP schema: initdb/oltp_schema.sql
  - OLAP schema: initdb/olap_schema.sql
  - Python 3.11 virtual environment under etl_process/venv/

Must be added before the complete test:
  - Kafka broker
  - Kafka Connect with Debezium PostgreSQL connector
  - Python ETL implementation
  - Airflow DAGs and task modules

  Host: localhost

  Password: postgres

STEP 0.5: Add Kafka and Kafka Connect to Compose
------------------------------------------------

Edit the root docker-compose.yaml and add:

  - Kafka broker reachable from the host at localhost:9092.
  - KRaft mode or a coordination service such as ZooKeeper.
  - Kafka Connect reachable from the host at localhost:8083.
  - Debezium PostgreSQL connector plugin installed in Kafka Connect.
  - Persistent Kafka data volumes.
  - A shared Compose network for PostgreSQL, Kafka, and Kafka Connect.

Kafka Connect must reach PostgreSQL using the Compose hostname postgres-db,
not localhost. Inside a container, localhost means that same container.

After editing Compose, run from the repository root:

  cd C:\Users\Administrator\localhost
  docker compose config
  docker compose up -d --build
  docker compose ps
  Test-NetConnection localhost -Port 9092
  Invoke-WebRequest http://localhost:8083/connector-plugins

Do not continue until port 9092 and the Kafka Connect endpoint respond.

STEP 0.6: Add Debezium Configuration
------------------------------------

Create:

  etl_process/config/debezium-connector.json

Use the current database contract:

  database.hostname: postgres-db

  plugin.name: pgoutput

Keep passwords out of committed configuration files. Inject them from local

================================================================================
PHASE 4: CONFIGURE DEBEZIUM CDC
================================================================================

Enable logical decoding in app:

  psql -h 127.0.0.1 -p 5432 -U postgres -d app -c "SHOW wal_level;"

Expected: logical.

Create the replication slot if it does not exist:

  psql -h 127.0.0.1 -p 5432 -U postgres -d app -c "SELECT * FROM pg_create_logical_replication_slot('debezium_slot', 'pgoutput');"

Create the publication if it does not exist:

  psql -h 127.0.0.1 -p 5432 -U postgres -d app -c "CREATE PUBLICATION debezium_pub FOR ALL TABLES;"

Register the connector:

  curl.exe -X POST http://127.0.0.1:8083/connectors -H "Content-Type: application/json" --data-binary "@etl_process/config/debezium-connector.json"

Verify:

  curl.exe http://127.0.0.1:8083/connectors/postgres-oltp-connector/status

Expected: connector state RUNNING and task state RUNNING.

Test a change:

  psql -h 127.0.0.1 -p 5432 -U postgres -d app -c "UPDATE users SET name = 'CDC Test User' WHERE user_id = 1;"

Confirm the corresponding users topic contains a Debezium event.

  airflow dags trigger oltp_to_olap_daily

Monitor all tasks and logs until the DAG completes successfully.

================================================================================
FINAL FULL-ETL SUCCESS CRITERIA
================================================================================

The full test passes only when:

  - app and sampleolapdata are reachable.
  - Kafka responds on localhost:9092.
  - Kafka Connect responds on localhost:8083.
  - Debezium connector and task are RUNNING.
  - CDC events appear in Kafka.
  - Python connectivity checks pass.
  - Unit and integration tests pass.
  - Airflow DAG parses and completes.
  - Data is transformed and loaded into sampleolapdata.
  - Duplicate/orphan checks return zero rows.
  - Data-quality checks pass.

Never use docker compose down -v during testing unless you intentionally want to
delete the PostgreSQL volume and rebuild all database data.
