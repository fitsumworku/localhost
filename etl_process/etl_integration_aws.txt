================================================================================
ETL AWS INTEGRATION GUIDE
Deploying the ETL Pipeline to AWS Production Environment
================================================================================

VERSION: 1.0
ENVIRONMENT: AWS Production
TARGET PLATFORM: EC2 + RDS + MSK + Lambda/ECS
LAST UPDATED: 2026-10-08

================================================================================
OVERVIEW
================================================================================

This guide covers the complete deployment of the ETL pipeline to AWS.
All components have been tested locally and are production-ready.

ARCHITECTURE OVERVIEW:
  OLTP Database (RDS PostgreSQL)
    ↓ (CDC via Debezium)
  Kafka Cluster (AWS MSK)
    ↓ (Event streaming)
  Python ETL Pipeline (EC2 or ECS)
    ↓ (Transform & Load)
  OLAP Database (RDS PostgreSQL)
    ↓ (Queries & Analytics)
  Airflow Orchestrator (EC2 or MWAA)

TOTAL DEPLOYMENT TIME: 4-8 hours
TEAM SIZE: DevOps + DBA + Backend Engineer

================================================================================
PREREQUISITES - VERIFY BEFORE STARTING
================================================================================

AWS Account Requirements:
  ☐ AWS Account with appropriate IAM permissions
  ☐ VPC created for production environment
  ☐ EC2 instances available (t3.large for Airflow, t3.xlarge for ETL)
  ☐ RDS PostgreSQL available
  ☐ AWS MSK (Managed Streaming for Kafka) available
  ☐ CloudWatch for logging and monitoring
  ☐ AWS Secrets Manager for credentials

Backend Requirements:
  ☐ OLTP schema finalized and stable (no pending changes)
  ☐ OLAP schema created and ready
  ☐ Table mappings documented
  ☐ All 13 base tables created in OLTP
  ☐ All dimension and fact tables created in OLAP

Network Requirements:
  ☐ Security groups configured
  ☐ VPC endpoints for AWS services
  ☐ VPN or bastion host for database access
  ☐ SSL/TLS certificates available

Data Requirements:
  ☐ OLTP database populated with initial data
  ☐ Backup of OLTP database created
  ☐ Backup of OLAP database created

PHASE 1: AWS INFRASTRUCTURE SETUP (1-2 hours)
================================================================================

STEP 1.1: Create RDS Instances for OLTP and OLAP
─────────────────────────────────────────────────

Create OLTP RDS Instance:

AWS Console → RDS → Create Database

Configuration:
  - Engine: PostgreSQL 14.x or higher
  - Multi-AZ: Yes (for HA)
  - Storage: 500 GB initial, auto-scaling enabled
  - Instance class: db.r6i.2xlarge (for production workload)
  - VPC: Production VPC
  - Security group: Allow port 5432 from ETL security group
  - Backup retention: 30 days
  - Encryption: KMS (AWS managed or customer managed)
  - Enable enhanced monitoring
  - Enable Performance Insights

Create OLAP RDS Instance:

AWS Console → RDS → Create Database

Configuration:
  - Engine: PostgreSQL 14.x or higher
  - Multi-AZ: Yes (for HA)
  - Storage: 1 TB initial, auto-scaling enabled
  - Instance class: db.r6i.4xlarge (larger for analytics workload)
  - VPC: Production VPC
  - Security group: Allow port 5432 from Airflow and ETL security groups
  - Backup retention: 30 days
  - Encryption: KMS (AWS managed or customer managed)
  - Enable enhanced monitoring
  - Enable Performance Insights

Verification:
  - Both databases accessible from ETL security group
  - Backups enabled and running
  - Parameter groups allow logical decoding (OLTP) and required extensions

STEP 1.2: Set Up AWS MSK Kafka Cluster
────────────────────────────────────────

Create MSK Cluster:

AWS Console → Amazon MSK → Create Cluster

Configuration:
  - Cluster name: etl-kafka-cluster
  - Kafka version: 3.2.x or higher
  - Number of brokers: 3 (production minimum)
  - Broker node type: kafka.m5.large
  - Storage per broker: 100 GB
  - Broker subnets: 3 AZs
  - Security groups: Allow port 9092 from ETL and Kafka Connect security groups
  - Encryption: Enabled (TLS)
  - Authentication: SASL/SCRAM (recommended) or mTLS
  - Monitoring: CloudWatch (all metrics enabled)
  - Logs: CloudWatch Logs (broker logs enabled)

Kafka Connect:

Option A: AWS Lambda for Kafka Connect (Serverless)
  - Simpler deployment
  - Auto-scaling
  - Pay per invocation

Option B: EC2-based Kafka Connect (Recommended for CDC)
  - More control
  - Better for stateful operations
  - Dedicated instance: t3.xlarge
  - Security group: Allow 8083 from Airflow
  - IAM role: Permissions to access RDS, MSK, CloudWatch

Install Debezium on Kafka Connect:
  
  # If using EC2:
  ssh -i key.pem ec2-user@kafka-connect-instance
  
  # Download Debezium PostgreSQL Connector
  cd /opt/kafka-connect/plugins
  aws s3 cp s3://debezium-releases/debezium-connector-postgres-2.5.0-plugin.tar.gz .
  tar -xzf debezium-connector-postgres-2.5.0-plugin.tar.gz
  
  # Update kafka-connect-distributed.properties
  echo "plugin.path=/opt/kafka-connect/plugins" >> config/connect-distributed.properties
  
  # Restart Kafka Connect
  systemctl restart kafka-connect

Verification:
  - MSK cluster running (3 brokers healthy)
  - Kafka Connect service running
  - Ability to create topics via AWS CLI

───────────────────────────────

ETL Pipeline Instance:

AWS Console → EC2 → Launch Instance

PHASE 2: DATABASE PREPARATION (30-45 minutes)
================================================================================

STEP 2.1: Initialize OLTP Database
───────────────────────────────────

Connect to RDS OLTP:
  psql -h prod-oltp.rds.amazonaws.com -U postgres -d oltp_db

Run Initialization Scripts:
  
  # Enable logical decoding
  ALTER SYSTEM SET wal_level = logical;
  SELECT pg_reload_conf();
  
  # Create debezium user
  CREATE USER debezium_user WITH PASSWORD 'PASSWORD_FROM_SECRETS_MANAGER';
  GRANT CONNECT ON DATABASE oltp_db TO debezium_user;
  GRANT REPLICATION ON DATABASE oltp_db TO debezium_user;
  GRANT USAGE ON SCHEMA public TO debezium_user;
  GRANT SELECT ON ALL TABLES IN SCHEMA public TO debezium_user;

Create Replication Slot:
  SELECT * FROM pg_create_logical_replication_slot('debezium_slot', 'pgoutput');

Create Publication:
  CREATE PUBLICATION debezium_pub FOR ALL TABLES;

Verify Setup:
  SELECT * FROM pg_replication_slots;  -- Should show debezium_slot
  SELECT * FROM pg_publication;         -- Should show debezium_pub

STEP 2.2: Initialize OLAP Database
───────────────────────────────────

Connect to RDS OLAP:
  psql -h prod-olap.rds.amazonaws.com -U postgres -d olap_db

Create ETL User:
  CREATE USER etl_user WITH PASSWORD 'PASSWORD_FROM_SECRETS_MANAGER';
  GRANT CONNECT ON DATABASE olap_db TO etl_user;
  GRANT USAGE ON SCHEMA public TO etl_user;
  GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO etl_user;
  GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO etl_user;
  ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES TO etl_user;
  ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON SEQUENCES TO etl_user;

Create Tracking Tables:
  
  -- Pipeline runs tracking
  CREATE TABLE IF NOT EXISTS etl_pipeline_runs (
    run_id BIGSERIAL PRIMARY KEY,
    dag_id VARCHAR(255) NOT NULL,
    run_date DATE NOT NULL,
    task_name VARCHAR(100),
    status VARCHAR(20),
    started_at TIMESTAMP,
    finished_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    error_message TEXT
  );
  CREATE INDEX idx_etl_runs_status ON etl_pipeline_runs(status, created_at);
  
  -- Kafka offset tracking
  CREATE TABLE IF NOT EXISTS kafka_offsets (
    topic VARCHAR(256) NOT NULL,
    partition INT NOT NULL,
    offset BIGINT NOT NULL,
    processed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (topic, partition)
  );
  
  -- Data quality issues
  CREATE TABLE IF NOT EXISTS data_quality_issues (
    issue_id BIGSERIAL PRIMARY KEY,
    run_id BIGINT REFERENCES etl_pipeline_runs(run_id),
    check_name VARCHAR(100),
    issue_description TEXT,
    severity VARCHAR(20),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );

Create Required Extensions:
  CREATE EXTENSION IF NOT EXISTS plpgsql;
  CREATE EXTENSION IF NOT EXISTS pg_stat_statements;

Enable Audit Logging:
  ALTER DATABASE olap_db SET pgaudit.log = 'READ,WRITE,DDL';
  CREATE EXTENSION IF NOT EXISTS pgaudit;

Verification:
  \du etl_user                                    -- Should show user created
  SELECT COUNT(*) FROM etl_pipeline_runs;        -- Should return 0
  SELECT COUNT(*) FROM kafka_offsets;            -- Should return 0

STEP 2.3: Create Initial Data (Optional)
──────────────────────────────────────────

If you want to seed OLAP with current OLTP data:

Create Snapshot Loader Script:
  
  Create file: /opt/etl/scripts/load_olap_snapshot.py
  
  This script:
  1. Connects to OLTP database
  2. Extracts all data from each table
  3. Transforms and loads to OLAP
  4. Sets initial Kafka offsets
  5. Records etl_pipeline_runs entry

Run Snapshot Load:

  cd /opt/etl
  python scripts/load_olap_snapshot.py
  
  Expected time: 30-60 minutes depending on data volume

Verification:
  SELECT COUNT(*) FROM users;                    -- Should show row count
  SELECT * FROM etl_pipeline_runs ORDER BY created_at DESC LIMIT 1;

PHASE 3: APPLICATION DEPLOYMENT (1-2 hours)
================================================================================

STEP 3.1: Deploy Python ETL Pipeline
──────────────────────────────────────

SSH to ETL Instance:
  ssh -i prod-key.pem ec2-user@etl-pipeline-prod.internal

Clone Repository:
  cd /opt
  git clone https://[YOUR_REPO]/team-project.git
  cd team-project

Create Python Virtual Environment:
  python3 -m venv /opt/etl-venv
  source /opt/etl-venv/bin/activate
  pip install --upgrade pip
  pip install -r etl-pipeline/requirements.txt

Create .env File (from AWS Secrets):
  Create script: /opt/scripts/setup_env.sh
  
  #!/bin/bash
  export OLTP_HOST=$(aws secretsmanager get-secret-value --secret-id prod/oltp/credentials --query SecretString --output text | jq -r .host)
  export OLTP_USER=$(aws secretsmanager get-secret-value --secret-id prod/oltp/credentials --query SecretString --output text | jq -r .username)
  export OLTP_PASSWORD=$(aws secretsmanager get-secret-value --secret-id prod/oltp/credentials --query SecretString --output text | jq -r .password)
  export OLTP_DATABASE=oltp_db
  export OLAP_HOST=$(aws secretsmanager get-secret-value --secret-id prod/olap/credentials --query SecretString --output text | jq -r .host)
  export OLAP_USER=$(aws secretsmanager get-secret-value --secret-id prod/olap/credentials --query SecretString --output text | jq -r .username)
  export OLAP_PASSWORD=$(aws secretsmanager get-secret-value --secret-id prod/olap/credentials --query SecretString --output text | jq -r .password)
  export OLAP_DATABASE=olap_db
  export KAFKA_BROKERS=$(aws secretsmanager get-secret-value --secret-id prod/kafka/credentials --query SecretString --output text | jq -r .bootstrap_servers)
  export LOG_LEVEL=INFO
  export BATCH_SIZE=5000
  export BATCH_TIMEOUT_SEC=60
  export MAX_RETRIES=5
  
  chmod +x /opt/scripts/setup_env.sh

Test Connectivity:
  /opt/scripts/setup_env.sh
  source /opt/etl-venv/bin/activate
  python etl-pipeline/test_connectivity.py
  
  Expected output:
  ✅ OLTP Connected
  ✅ OLAP Connected
  ✅ Kafka Connected

Create Systemd Service:
  
  Create file: /etc/systemd/system/etl-pipeline.service
  
  [Unit]
  Description=ETL Pipeline Service
  After=network.target
  
  [Service]
  Type=simple
  User=etl
  ExecStart=/bin/bash -c 'source /opt/scripts/setup_env.sh && source /opt/etl-venv/bin/activate && python -m etl_pipeline.main'
  Restart=always
  RestartSec=10
  StandardOutput=journal
  StandardError=journal
  SyslogIdentifier=etl-pipeline
  
  [Install]
  WantedBy=multi-user.target
  
  Enable and start:
  sudo systemctl daemon-reload
  sudo systemctl enable etl-pipeline
  sudo systemctl start etl-pipeline
  sudo systemctl status etl-pipeline

Monitor Logs:
  sudo journalctl -u etl-pipeline -f

STEP 3.2: Deploy Airflow
─────────────────────────

Option A: EC2-based Airflow

SSH to Airflow Instance:
  ssh -i prod-key.pem ec2-user@airflow-prod.internal

Install Airflow:
  python3 -m venv /opt/airflow-venv
  source /opt/airflow-venv/bin/activate
  pip install apache-airflow==2.7.0
  pip install apache-airflow-providers-postgres==5.9.0
  pip install apache-airflow-providers-apache-kafka==1.2.0
  pip install python-dotenv

Initialize Airflow:
  export AIRFLOW_HOME=/opt/airflow
  airflow db init
  
  # Create admin user
  airflow users create \
    --username admin \
    --firstname Admin \
    --lastname User \
    --role Admin \
    --email admin@company.com \
    --password STRONG_PASSWORD

Configure Airflow for RDS:

  Create file: /opt/airflow/airflow.cfg
  
  [database]
  sql_alchemy_conn = postgresql://airflow:PASSWORD@prod-airflow-rds.rds.amazonaws.com:5432/airflow
  
  [core]
  dags_folder = /opt/airflow/dags
  load_examples = False
  load_default_connections = False
  
  [webserver]
  base_log_folder = /opt/airflow/logs
  expose_config = False
  
  [scheduler]
  dag_dir_list_interval = 300

Copy DAG Files:
  cp -r /opt/team-project/airflow/dags/* /opt/airflow/dags/

Create Systemd Services:

  Webserver: /etc/systemd/system/airflow-webserver.service
  [Unit]
  Description=Airflow Webserver
  After=network.target
  
  [Service]
  User=airflow
  ExecStart=/opt/airflow-venv/bin/airflow webserver --port 8080
  Restart=always
  
  [Install]
  WantedBy=multi-user.target
  
  Scheduler: /etc/systemd/system/airflow-scheduler.service
  [Unit]
  Description=Airflow Scheduler
  After=network.target
  
  [Service]
  User=airflow
  ExecStart=/opt/airflow-venv/bin/airflow scheduler
  Restart=always
  
  [Install]
  WantedBy=multi-user.target
  
  Enable and start:
  sudo systemctl daemon-reload
  sudo systemctl enable airflow-webserver airflow-scheduler
  sudo systemctl start airflow-webserver airflow-scheduler

Configure Database Connections:

  airflow connections add oltp_db \
    --conn-type postgres \
    --conn-host prod-oltp.rds.amazonaws.com \
    --conn-login debezium_user \
    --conn-password XXXX \
    --conn-schema oltp_db \

    --conn-type postgres \
    --conn-host prod-olap.rds.amazonaws.com \

STEP 3.3: Set Up Debezium Connector
─────────────────────────────────────

Create Connector Configuration:

Create file: /opt/scripts/debezium-connector-config.json

{
  "name": "postgres-oltp-connector",
  "config": {
    "connector.class": "io.debezium.connector.postgres.PostgresConnector",
    "database.hostname": "prod-oltp.rds.amazonaws.com",
    "database.port": 5432,
    "database.user": "debezium_user",
    "database.password": "PASSWORD",
    "database.dbname": "oltp_db",
    "database.server.name": "prod.oltp",
    "plugin.name": "pgoutput",
    "slot.name": "debezium_slot",
    "publication.name": "debezium_pub",
    "topic.prefix": "cdc.prod.oltp",
    "transforms": "route",
    "transforms.route.type": "org.apache.kafka.connect.transforms.RegexRouter",
    "transforms.route.regex": "([^.]+)\\.([^.]+)\\.([^.]+)\\.([^.]+)",
    "transforms.route.replacement": "$4",
    "max.batch.size": 2048,
    "poll.interval.ms": 1000,
    "snapshot.mode": "initial",

Register Connector:

Monitor Progress:

PHASE 4: SECURITY HARDENING (30-45 minutes)
================================================================================

STEP 4.1: Network Security
────────────────────────────

VPC Configuration:
  ☐ All resources in private subnets
  ☐ NAT gateway for outbound internet
  ☐ VPC endpoints for AWS services (S3, Secrets Manager, CloudWatch)
  ☐ Network ACLs configured

Security Groups:

ETL Pipeline Security Group:
  - Inbound: 22 (SSH) from Bastion, 9092 (Kafka) from self
  - Outbound: 5432 (RDS), 9092 (MSK), 443 (HTTPS to AWS), 80 (NTP)

Airflow Security Group:
  - Inbound: 22 (SSH) from Bastion, 8080 (HTTP) from ALB
  - Outbound: 5432 (RDS), 9092 (MSK), 443 (HTTPS to AWS)

RDS Security Groups:
  - OLTP: Allow port 5432 from ETL, Kafka Connect, Bastion
  - OLAP: Allow port 5432 from ETL, Airflow, Bastion

MSK Security Groups:
  - Allow port 9092 from ETL, Kafka Connect, Airflow
  - Allow port 2181 (ZooKeeper) from Kafka Connect only

STEP 4.2: Database Security
─────────────────────────────

Enable RDS Encryption:
  ☐ Enable encryption at rest (KMS)
  ☐ Enable encryption in transit (SSL)
  ☐ Configure backup encryption
  ☐ Enable enhanced monitoring

PHASE 5: MONITORING & LOGGING (30 minutes)

STEP 5.1: CloudWatch Setup
────────────────────────────

Create CloudWatch Log Groups:

  /aws/etl/pipeline
  /aws/airflow/logs
  /aws/kafka/broker-logs
  /aws/rds/oltp
  /aws/rds/olap

Set Up CloudWatch Alarms:

ETL Pipeline Alarms:
  - High memory usage (> 80%)
  - High CPU usage (> 80%)
  - Kafka consumer lag > 100,000 messages
  - Errors in logs

Airflow Alarms:
  - DAG failure
  - Task timeout
  - Scheduler not running
  - High web server latency

RDS Alarms:
  - Database connections > 80% of max
  - CPU utilization > 80%
  - Free storage space < 10%
  - Replication lag > 1 second

MSK Alarms:
  - Broker node failures
  - Topic replication failing
  - High ZooKeeper CPU

COST OPTIMIZATION
================================================================================

Right-Sizing:
  - Start with t3.xlarge for ETL/Airflow
  - Monitor utilization
  - Scale down if CPU/memory < 20%
  - Scale up if approaching limits

Kafka Optimization:
  - MSK costs: $0.1/hour per broker
  - Start with 3 brokers, monitor lag
  - Retention: Keep at 7 days minimum
  - Compression: Enable snappy compression

Database Optimization:
  - RDS: Choose appropriate instance size
  - Storage: Monitor growth, set auto-scaling
  - Backups: Adjust retention to 30 days
  - Reserved instances: Purchase for 1-3 years

Cost Monitoring:
  - Set up AWS Budget alerts
  - Review costs monthly
  - Analyze by component
  - Optimize over time

================================================================================
DISASTER RECOVERY
================================================================================

Backup Strategy:

OLTP Database:
  - Automated daily backups (30 days)
  - Read replica in different AZ
  - Test restore quarterly

OLAP Database:
  - Automated daily backups (30 days)
  - Test restore quarterly
  - Optional: Read replica for HA

Kafka:
  - MSK handles replication (3 replicas)
  - 7-day retention for recovery
  - Schema registry backed up

Recovery Procedures:

If OLTP Corrupted:
  1. Restore from latest backup
  2. Rebuild replication slot
  3. Restart Debezium connector
  4. Catch up OLAP with snapshot

If OLAP Corrupted:
  1. Restore from latest backup
  2. Update Kafka offsets
  3. Re-run failed DAG tasks
  4. Verify data integrity

If Kafka Cluster Down:
  1. MSK auto-recovery with multi-AZ
  2. Manual recovery: restore from snapshot
  3. Debezium resumes from replication slot

RTO/RPO Targets:
  - RTO (Recovery Time Objective): < 4 hours
  - RPO (Recovery Point Objective): < 1 hour

TROUBLESHOOTING GUIDE - AWS SPECIFIC
================================================================================

Issue: RDS Connection Timeout
  
  Diagnosis:
  - Check security group allows port 5432
  - Verify RDS instance is running
  - Check network connectivity from ETL instance
  - Verify credentials in Secrets Manager
  
  Resolution:
  - Update security group rules
  - Restart RDS instance if needed
  - Use bastion host to test connection

Issue: Kafka Broker Unreachable

  Diagnosis:
  - Check MSK cluster status in console
  - Verify security group allows port 9092
  - Check broker node health
  
  Resolution:
  - Wait for broker recovery
  - Manually restart broker if failed
  - Scale cluster if repeated issues

Issue: High Kafka Consumer Lag

  Diagnosis:
  - Check ETL instance CPU/memory
  - Check OLAP disk I/O
  - Verify network latency
  
  Resolution:
  - Increase ETL instance size
  - Optimize OLAP queries
  - Add indexes to OLAP tables
  - Reduce batch size to process faster

Issue: DAG Not Running on Schedule

  Diagnosis:
  - Check if scheduler running: systemctl status airflow-scheduler
  - Check DAG parse errors in UI
  - Verify cron expression
  - Check Airflow metadata database
  
  Resolution:
  - Restart scheduler
  - Fix DAG syntax errors
  - Manually trigger DAG to test

Issue: CloudWatch Metrics Missing

  Diagnosis:
  - Check IAM role has CloudWatch permissions
  - Verify log groups exist
  - Check agent/service publishing metrics
  
  Resolution:
  - Add cloudwatch:PutMetricData to IAM role
  - Create log groups manually if needed
  - Restart services to resume publishing

  # List DAGs

  # Trigger DAG
  airflow dags trigger [dag_id]
  
  # Clear tasks

  # Check replication status
